# Data format

## Existing Stage 0A test

T0001.BIN through T9999.BIN contain 262,144 pattern bytes with no header. For zero-based absolute byte offset `i`, expected byte is `(i * 17 + (i >> 8) + 0x5A) & 0xFF`. This is a storage test, not a sensor recording format.

## Stage 0B — raw synthetic samples (0.2.0)

Each sample is exactly 12 bytes: six little-endian signed 16-bit integers. No header, padding or footer. Slot n, channel c=0..5 is `((n*(2*c+1)+997*c) mod 65536)-32768`. First sample is [-32768,-31771,-30774,-29777,-28780,-27783]. File length is 12 times the persisted sample count. Files increment from highest existing RUN number, never filling gaps.

The validator requires the expected sample count from the Serial PASS line and rejects size, pattern and sequence disagreement. The pattern repeats after 65536 slots; byte-only validation cannot detect loss of an entire pattern period. Preserve Serial duration, count and loss counters as essential evidence. An interrupted file has no embedded completion indicator. A firmware PASS requires zero reported losses and full size/CRC read-back. No real IMU or optical data is stored yet.

This deliberately simple layout supersedes the proposed header/footer format for Phase 0B following the user's request. Future integrated recordings require a separately versioned format with timestamps and metadata.

Firmware 0.2.4 prints separate storage CRC/read-back and sample-continuity results. CRC validates stored bytes against bytes submitted, including declared gaps; only zero-loss runs pass continuity. On stop the current eligible synthetic slot may be generated by the stop path before quiescence.

## Optical event files — optical-events-v1, firmware 0.4.0

Standalone Stage 1 writes 16-byte records: sequence u64 LE at offset 0 (1..N), candidate-edge elapsed microseconds since session start u64 LE at offset 8. No header/footer or padding. Accepted events only. Filenames `OPT_YYYY-MM-DD_HH-MM-SS_0001.BIN` use user-set UTC, with a collision suffix. Unset clocks use `OPT_UNSET_<boot-id>_UP<uptime-seconds>_0001.BIN`. No fabricated wall time and no changes to earlier RUN file formats.

Serial retains duration, configuration, counts, errors and CRC32; it is required completion evidence. The standalone validator requires expected event count and CRC from Serial, checks contiguous sequence and strictly increasing elapsed timestamps. CRC32 is standard IEEE/ISO-HDLC as Python zlib.crc32. An empty stopped session has zero records and CRC 00000000. There is no standalone clean-stop marker or protection against clock drift; SD validation cannot establish one detection per physical revolution. See [optical instructions](../Stage1_Optical_Test/README.txt).

## Naming update — optical firmware 0.6.1

Raw optical-events-v1 bytes are unchanged. Untimed files now use `/OPT_0002.BIN`; timed files retain `/OPT_YYYY-MM-DD_HH-MM-SS_0004.BIN`. Both modes consume one shared persistent device run index. A reserved number can be skipped after failure/collision/power interruption; it is not reused. Migration uses remaining optical-file count/highest filename index as a lower bound, not recovered deleted history. See the standalone README for clock/NVS behaviour. Existing UNSET recordings stay readable and unchanged.
